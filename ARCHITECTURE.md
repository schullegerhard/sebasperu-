# SebasPeru — Production Architecture

Implements the recommended stack:

| System Component | Technology | Folder |
|---|---|---|
| **Public Storefront (SEO)** | **Next.js** (App Router, SSR/SSG) | `storefront/` |
| **Admin Panel** | **React + Vite** | `./` (existing app, `/admin`) |
| **Backend / API** | **Node.js + Express** | `api/` |
| **Database** | **PostgreSQL** (in-memory fallback) | `api/db/` |

```
ecsite/
├── src/ …                 # Vite app  → storefront (legacy) + ADMIN PANEL (/admin)
├── storefront/            # NEXT.JS public storefront (SEO-friendly, SSR)
│   ├── app/               #   App Router pages (home, categoria, producto, …)
│   ├── components/        #   Header/Footer/ProductCard/CartProvider (client islands)
│   └── lib/data.js        #   data layer → reads API if NEXT_PUBLIC_API_URL, else local catalog
└── api/                   # EXPRESS API
    ├── src/               #   index.js, store.js (pg|memory), auth.js (JWT)
    └── db/schema.sql      #   PostgreSQL schema
```

## Why this split
- **Storefront → Next.js**: product/category pages are **server-rendered** so crawlers, Bing, and social previews get full HTML — title, meta description, canonical, and **Schema.org Product JSON-LD** — *before any JS runs*. This is the SEO win over the Vite SPA.
- **Admin → React + Vite**: it's behind a login, needs no SEO, and benefits from Vite's fast SPA DX.
- **One Express API** serves both front-ends; **PostgreSQL** for real persistence.

## Run it locally

### 1) API (Express)
```bash
cd api
npm install
cp .env.example .env          # works out-of-the-box in IN-MEMORY mode (no DB needed)
npm start                     # http://localhost:4000  (GET /api/health)
```
**With PostgreSQL / Supabase** (permanent storage):
```bash
# 1) Create a free project at supabase.com
# 2) Project → Connect → "Session pooler" → copy the URI
# 3) Put it in api/.env as DATABASE_URL=postgresql://postgres.xxxx:[PASSWORD]@...pooler.supabase.com:5432/postgres
npm start          # auto-creates tables + seeds the catalog on first boot → "postgres mode"
# (optional) npm run db:seed   # force a clean reseed
```
SSL is enabled automatically for non-localhost hosts. No `psql` required — the API runs `db/schema.sql` and seeds itself via `src/migrate.js`.

### 2) Storefront (Next.js)
```bash
cd storefront
npm install
# .env.local sets NEXT_PUBLIC_API_URL=http://localhost:4000 (falls back to local catalog if API is down)
npm run dev                   # http://localhost:3000
npm run build && npm start    # production (SSG/SSR)
```

### 3) Admin (Vite) — unchanged
```bash
npm install && npm run dev    # http://localhost:5173/admin
```

## API endpoints
| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/health` | – | status + db mode |
| GET | `/api/products` | – | all products |
| GET | `/api/products/:slug` | – | one product |
| GET | `/api/categories` | – | all categories + subcategories |
| GET | `/api/categories/:slug` | – | one category |
| GET | `/api/categories/:slug/products` | – | products in category |
| POST | `/api/orders` | – | create order (from checkout) |
| GET | `/api/orders` | **Bearer** | list orders (staff roles) |
| POST | `/api/auth/login` | – | returns JWT |
| GET | `/api/me` | **Bearer** | current user |

Auth uses **bcrypt** (hashed passwords) + **JWT** (8h). Demo: `admin@sebasperu.com` / `admin123`.

## SEO proof
`curl http://localhost:3000/producto/laptop-hp-250-g9` returns server HTML containing the `<title>`, `meta description`, `<link rel="canonical">`, the **Product JSON-LD**, and the product name + price — all without executing JavaScript. `/sitemap.xml` and `/robots.txt` are generated by Next automatically.

## Admin ↔ API (one source of truth)
The **admin panel now talks to the same API** as the storefront:
- Login goes through `POST /api/auth/login` → **JWT** stored in `localStorage` and sent as `Authorization: Bearer` on every request (`src/services/http.js`).
- All admin reads/writes (products, categories, orders, customers, coupons, settings) hit the API (`src/services/api.js`); pages load asynchronously.
- Write endpoints are **role-protected** server-side (e.g. only Administrador creates products; Almacén updates stock/dispatch; Marketing manages coupons/settings) — the UI gating is backed by real API checks.
- The storefront **checkout** `POST`s to `/api/orders`, so a purchase shows up immediately in the admin's Pedidos. Verified end-to-end (52/52 tests).

Set the admin's API base via `.env` → `VITE_API_URL=http://localhost:4000`.

## Deploy

### Single-origin mode (used for the live demo)
The API can serve the built Vite SPA, so **one origin** exposes the storefront, the admin, and `/api` (no CORS, one URL):
```bash
npx vite build          # builds /dist with relative /api (uses .env.production)
cd api && npm start      # Express serves /dist + /api on :4000  → expose :4000 publicly
```
Live now via an ngrok tunnel on `:4000` (temporary, tied to the dev machine — free ngrok shows a one-time “Visit Site” interstitial). Verified: public admin login → dashboard + products from Supabase.

### Permanent cloud deploy (recommended)
Artifacts are ready: `api/Dockerfile`, `api/Procfile`, root `render.yaml`.
- **Render**: New → Blueprint → connect the repo → set `DATABASE_URL` (your Supabase URI) and `CORS_ORIGIN` in the dashboard. `JWT_SECRET` is auto-generated. Health check: `/api/health`.
- **Railway / Fly**: import the repo (root `api/`), set the same env vars; Railway auto-detects Node, Fly uses the Dockerfile.
- **Storefront (Next.js)** → Vercel (rootDir `storefront/`), set `NEXT_PUBLIC_API_URL` to the API's public URL.

These steps need your hosting account login (I can't create it). Once `DATABASE_URL` points at Supabase, data persists across deploys/restarts.

## Production notes
- Deploy storefront on Vercel (native Next.js), API on Render/Railway/Fly, Postgres managed (Neon/Supabase/RDS).
- Move `JWT_SECRET` and `DATABASE_URL` to real secrets; add rate-limiting + HTTPS at the edge.
- For a public demo, the API must also be reachable from the browser: tunnel/host it and rebuild the front-ends with `VITE_API_URL` / `NEXT_PUBLIC_API_URL` pointing at its public URL (localhost only works on the same machine).
